# ZigDash v1.9.1 Android Release Artifacts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and deliver the signed ZigDash `1.9.1+20` Android App Bundle and English Google Play release notes to Windows Downloads.

**Architecture:** Validate the existing release-signing inputs without printing secrets, build with Flutter's release app-bundle pipeline, then verify and copy the immutable output. Generate one UTF-8 notes file from approved user-facing copy and verify both delivered artifacts with hashes.

**Tech Stack:** Flutter, Android Gradle Plugin, Java `keytool`, POSIX file utilities, SHA-256.

---

## File structure

- Read: `pubspec.yaml` — authoritative version name and build number.
- Read: `android/key.properties` — gitignored release-signing references; values remain secret.
- Read: `android/app/build.gradle.kts` — release signing and app-bundle configuration.
- Generate: `build/app/outputs/bundle/release/app-release.aab` — Flutter build output.
- Deliver: `C:\Users\gilad\Downloads\ZigDash-1.9.1+20-release.aab` — verified release bundle.
- Deliver: `C:\Users\gilad\Downloads\ZigDash-1.9.1-release-notes-en.txt` — Google Play notes.

### Task 1: Validate clean source and release signing

- [ ] **Step 1: Confirm source version and cleanliness**

Run:

```bash
git status --short
grep '^version: 1.9.1+20$' pubspec.yaml
```

Expected: no uncommitted files and exactly `version: 1.9.1+20`.

- [ ] **Step 2: Validate signing references without printing secrets**

Read `android/key.properties` in a script that checks the presence of
`storeFile`, `storePassword`, `keyAlias`, and `keyPassword`, resolves
`storeFile` relative to `android/`, and prints only whether each field and the
keystore file exist.

Expected: all four properties and the referenced keystore exist.

- [ ] **Step 3: Validate the configured alias**

Run `keytool -list` using the configured keystore and alias while keeping
password values out of command output.

Expected: exit code 0 and the configured alias exists.

### Task 2: Build and verify the Android App Bundle

- [ ] **Step 1: Build the release bundle**

Run:

```bash
flutter build appbundle --release
```

Expected: exit code 0 and Flutter reports
`build/app/outputs/bundle/release/app-release.aab`.

- [ ] **Step 2: Verify the generated bundle**

Run:

```bash
test -s build/app/outputs/bundle/release/app-release.aab
unzip -t build/app/outputs/bundle/release/app-release.aab
```

Expected: the file is non-empty and `unzip` reports no errors.

- [ ] **Step 3: Copy the verified bundle**

Copy the build output to:

```text
/mnt/c/Users/gilad/Downloads/ZigDash-1.9.1+20-release.aab
```

Use a temporary sibling filename and atomic rename so an earlier Downloads
artifact is not overwritten by a partial copy.

### Task 3: Create and verify Google Play release notes

- [ ] **Step 1: Write approved English notes**

Write this UTF-8 text, including no heading or Play Console markup:

```text
ZigDash now makes connection problems clearer and safer. Last-known Zigbee2MQTT values stay visible while offline, with stale indicators and broker-dependent controls disabled until fresh data returns. Reconnect status and retry actions are easier to understand, while ZigDash remains private, local-only, account-free, and tracker-free.
```

- [ ] **Step 2: Verify Play note constraints**

Check that the file decodes as UTF-8 and contains no more than 500 Unicode
characters.

Expected: valid UTF-8 and a character count at or below 500.

### Task 4: Verify delivery

```bash

  /mnt/c/Users/gilad/Downloads/ZigDash-1.9.1-release-notes-en.txt
```
