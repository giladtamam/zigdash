# ZigDash v1.9.1 Android Release Artifacts

## Goal

Produce the Google Play Android App Bundle for ZigDash `1.9.1+20` and concise
English Google Play release notes, then place both artifacts in the user's
Windows Downloads directory.

## Inputs and signing

- Build the clean local `main` branch at version `1.9.1+20`.
- Use the existing Android release signing configuration in
  `android/key.properties` when present.
- Before delivery, verify that release signing is configured. Do not deliver a
  debug-signed fallback as a Google Play artifact.
- Do not print or copy signing secrets into logs or release artifacts.

## Outputs

Create these files in `C:\Users\gilad\Downloads`:

- `ZigDash-1.9.1+20-release.aab`
- `ZigDash-1.9.1-release-notes-en.txt`

The notes file is UTF-8 plain text and stays below Google Play's 500-character
limit. It describes user-visible benefits: clearer reconnect status, preserved
last-known values, disabled broker-dependent controls while offline, and
continued privacy-first/local-only operation. It avoids internal implementation
details and unsupported claims.

## Build and verification

1. Confirm the Git worktree is clean and the application version is
   `1.9.1+20`.
2. Confirm release signing properties and the referenced keystore exist without
   exposing their values.
3. Run `flutter build appbundle --release`.
4. Verify the generated AAB exists, is non-empty, and is a valid ZIP container.
5. Copy the AAB to the exact Downloads filename and write the approved notes.
6. Verify both delivered files, report their sizes and SHA-256 hashes, and leave
   source files unchanged apart from this design document.

## Failure handling

If signing or the release build fails, do not substitute a debug-signed bundle.
Report the exact non-secret error and leave any prior Downloads artifact
untouched unless a newly built release bundle has been verified.
